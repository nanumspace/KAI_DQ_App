# 5. 자주 묻는 질문

## 설치와 실행

**설치 파일을 실행하면 보안 경고가 뜹니다.**
설치 파일은 코드 서명과 공증이 되어 있어 정상 파일이면 경고가 뜨지 않습니다. 경고가 뜨면 내려받기 중 손상되었거나 Release 페이지가 아닌 곳에서 받은 파일입니다. Release 페이지에서 다시 받고, 필요하면 `SHA256SUMS.txt` 와 대조합니다.

**인터넷이 안 되는 PC에서도 되나요?**
됩니다. 프로그램은 네트워크 통신을 하지 않으며 명세와 규칙이 안에 들어 있습니다.

**실행 이력은 어디에 저장되나요?**
사용자 컴퓨터의 앱 데이터 폴더에 DuckDB 파일 하나로 저장됩니다. 위치는 **설정** 화면에서 볼 수 있습니다. 다른 곳으로 전송되지 않습니다.

**얼마나 큰 데이터까지 되나요?**
환자 2,000명, 행 50만(30MB) 규모를 10초 안팎에 처리합니다. 메모리는 1GB 미만을 씁니다. 그보다 크면 시간이 비례해 늘지만 나눠 넣을 필요는 없습니다.

## 입력 파일

**EHR 추출본과 서식, 둘 다 꼭 있어야 하나요?**
검증은 EHR 추출본만으로도 됩니다(서식으로 만드는 표는 '테이블 없음'으로 나옵니다). 그러나 제출본은 둘 다 있어야 합니다. 병리·바이오마커·병기처럼 EHR 에 구조화되어 있지 않은 항목이 서식으로만 들어오기 때문입니다.

**서식 변환 결과만 넣었더니 실행이 막힙니다.**
PERSON 이 없어서입니다. 서식은 환자·방문·약물·사망·검체·기록 표를 만들지 못합니다. EHR 추출본 폴더를 함께 넣습니다. **폴더 선택**에서 두 폴더를 한 번에 고르거나, 두 폴더를 담은 상위 폴더를 넣습니다.

**같은 표가 두 폴더에 있다고 나옵니다.**
정상입니다. EHR 추출본의 MEASUREMENT(검사 결과)와 서식 변환 결과의 MEASUREMENT(병기 평가)는 합쳐 읽습니다. 사전 점검이 "2개 파일을 합쳐 읽습니다"로 알려 줍니다. 같은 행이 두 벌 들어 있으면 키 중복으로 보고됩니다.

**테스트용 데이터가 있나요?**
있습니다. 앱의 **입력 양식 내려받기 → 견본 데이터**는 오류 없는 clean 데이터이고, GitHub Release 페이지의 **견본 데이터 zip** 에는 오류를 주입한 dirty 데이터와 정답표까지 들어 있습니다. 모두 가상데이터입니다. 순서는 [2. 입력 파일 준비](02-input.md)의 "견본 데이터로 먼저 시험하기"에 있습니다.

**파일을 넣었는데 표가 대응되지 않습니다.**
파일 이름에 표 이름이 없고 헤더도 명세 컬럼과 60% 미만으로 겹치면 자동 대응이 되지 않습니다. 대응표의 드롭다운에서 직접 고르거나, 파일 이름을 표 이름(예: `PERSON.csv`)으로 바꿉니다.

**엑셀 파일의 시트가 일부만 인식됩니다.**
시트 하나가 표 하나여야 합니다. 시트 이름에 표 이름을 넣으면 확실합니다. 첫 줄이 헤더가 아니거나 제목 행이 있으면 지웁니다.

**한글이 깨져 보입니다.**
파일이 EUC-KR인데 다른 인코딩으로 잘못 저장된 경우입니다. 병원 시스템에서 다시 내보내거나, 엑셀에서 열어 UTF-8 CSV로 저장합니다. 정상 EUC-KR 파일은 프로그램이 알아서 변환합니다. UTF-16("유니코드 텍스트")은 읽지 못하므로 UTF-8 로 저장합니다.

**컬럼 이름이 전부 대문자로 나옵니다.**
그대로 넣어도 됩니다. 소문자 명세 이름으로 맞춰 읽고 참고로 표시합니다.

**빈 칸에 `NULL` 이라고 적혀 나옵니다.**
그대로 넣어도 됩니다. `NULL`, `NA`, `N/A` 같은 글자는 빈 값으로 읽고, 몇 개였는지 보고서의 '입력 정규화'에 적습니다. 필수 항목이면 필수값 누락으로 보고됩니다.

**"기본키 또는 person_id 누락" 오류로 실행이 막힙니다.**
헤더에 그 표의 기본키(예: `visit_occurrence_id`)와 `person_id` 컬럼이 있어야 합니다. 컬럼 이름의 철자를 명세와 맞춥니다. 컬럼 명세서는 **입력 양식 내려받기**에서 받을 수 있습니다.

**날짜가 `2026/03/15`처럼 되어 있습니다.**
`YYYY-MM-DD`로 바꿔야 합니다. 엑셀에서는 셀을 날짜 형식으로 두면 프로그램이 변환합니다. CSV에서는 내보낼 때 형식을 지정합니다. `2026-03-15 00:00:00` 처럼 시각만 붙은 것은 알아서 날짜로 읽습니다.

## 서식

**서식의 코드를 어디서 보나요?**
**입력 양식 내려받기 → 서식 양식**으로 받은 폴더의 `README.txt` 에 서식마다 필드와 고를 수 있는 코드가 있습니다. 한글 라벨이 아니라 코드를 적습니다.

**서식 변환의 '확인할 점'에 "값 집합에 없는 코드"가 나옵니다.**
그 필드의 코드 목록에 없는 값입니다. README.txt 의 코드로 바꿉니다. 목록에 꼭 필요한 값이 없으면 중앙에 알려 주세요 — 값 집합을 보태는 것은 중앙의 일입니다.

**서식에 사례가 없는 환자는 어떻게 하나요?**
행을 만들지 않습니다. 서식 파일 자체가 없어도 되지만, 헤더만 있는 파일을 두면 "채우지 않은 것"이 아니라 "사례가 없는 것"임이 분명해집니다.

## 결과

**위반이 너무 많이 나옵니다. 어디부터 봐야 하나요?**
**결과 보고서**의 실패 규칙 목록을 위반 수 순으로 봅니다. 컬럼 구성 불일치나 데이터 타입 불일치처럼 형식 문제 하나가 수천 건을 만드는 경우가 많으니 형식 문제를 먼저 고치고 다시 실행합니다.

**보고서의 예시에 값이 `…` 로 나옵니다.**
일부러 가린 것입니다. `report.md` 는 병원 밖으로 나갈 수 있는 파일이라 ID·날짜·수치·원천 문자열을 싣지 않습니다. 실제 값은 **오류 현황 조회** 화면이나 `findings.csv` 에서 봅니다.

**미래 날짜 오류가 나오는데 실제로는 맞는 날짜입니다.**
검증 실행일 기준으로 판정합니다. **설정** 또는 실행 화면의 **검증 실행일**을 데이터 추출일로 맞추고 다시 실행합니다.

**규칙이 잘못됐다고 생각됩니다.**
그럴 수 있습니다. 규칙은 가상데이터로만 검증했고 실제 병원 데이터는 처음입니다. 규칙 id 와 왜 그렇게 생각하는지를 파일럿 피드백 양식에 적어 보내 주세요. 위반 행의 값은 보내지 않아도 됩니다.

**어떤 파일을 중앙에 보내나요?**
`submission.json` 하나입니다. `findings.csv`와 오류 현황에서 내보낸 CSV는 환자 단위 정보이므로 보내지 않습니다.

**규칙 내용을 미리 볼 수 있나요?**
**검증 규칙 관리** 화면에서 규칙을 검색해 설명, 검사 대상, 교차 규칙의 SQL, 조치 안내를 볼 수 있습니다.
