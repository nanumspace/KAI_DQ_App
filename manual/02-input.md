# 2. 입력 파일 준비

프로그램은 코호트 테이블을 **파일**로 받습니다. 병원 DB에서 테이블을 내보낸 뒤 아래 형태 중 하나로 준비합니다.

## 받는 형태 세 가지

| 형태 | 설명 |
|---|---|
| CSV 여러 개 | 파일 하나가 테이블 하나. UTF-8 또는 EUC-KR(자동 변환). 탭 구분(.tsv)도 됩니다 |
| 엑셀 한 파일 | 시트 하나가 테이블 하나. 날짜 셀은 자동으로 YYYY-MM-DD로 바뀝니다 |
| 폴더 | 위 파일들이 든 폴더를 통째로 |

## 어떤 테이블이 필요한가

코호트마다 필요한 테이블이 정해져 있습니다. 모든 코호트는 핵심 테이블 8개와 이상사례 테이블을 내며, 암과 림프종은 항암 테이블을 더 냅니다.

| 테이블 | 내용 | 모든 코호트 |
|---|---|---|
| PERSON | 환자 | O |
| VISIT_OCCURRENCE | 방문 | O |
| CONDITION_OCCURRENCE | 진단 | O |
| PROCEDURE_OCCURRENCE | 처치 | O |
| DRUG_EXPOSURE | 약물 | O |
| MEASUREMENT | 검사 | O |
| OBSERVATION | 관찰 | O |
| NOTE | 노트 | O |
| ADVERSE_EVENT | 이상사례 | O |
| ANTP_THERAPY | 항암요법 | 폐암, 유방암, 대장암, 림프종만 |
| 질환 특화 테이블 | LUNG_CANCER, BREAST_CANCER, COLORECTAL_CANCER, MASLD, DIABETES, LYMPHOMA 중 하나 | O |

테이블이 빠지면 "테이블 누락"으로 보고되고 그 테이블에 관한 규칙은 건너뜁니다.

## 값의 형식

| 항목 | 형식 |
|---|---|
| 문자 인코딩 | UTF-8 권장. EUC-KR(CP949)도 자동 인식해 변환합니다 |
| 헤더 | 첫 줄에 컬럼 이름. 명세의 컬럼 이름과 같아야 합니다 |
| 빈 값(NULL) | 빈 문자열. `NULL`, `NA`, `-` 같은 글자를 넣지 않습니다 |
| 날짜 | `YYYY-MM-DD` (예: 2026-03-15) |
| 타임스탬프 | `YYYY-MM-DD HH:MM:SS` |
| 숫자 | 숫자만. 단위나 쉼표를 넣지 않습니다 |

엑셀로 낼 때는 날짜 셀을 날짜 형식으로 두면 됩니다. 프로그램이 `YYYY-MM-DD`로 바꿉니다.

## 입력 양식 내려받기

**검증 실행** 화면의 **입력 양식 내려받기**에서 네 가지를 받을 수 있습니다.

| 양식 | 용도 |
|---|---|
| 엑셀 양식 (시트당 테이블, 명세 포함) | 시트마다 헤더가 채워진 빈 양식. 명세 시트가 함께 들어 있습니다 |
| CSV 양식 묶음 (헤더만) | 테이블별 CSV 헤더 파일 |
| 컬럼 명세서 (xlsx) | 테이블·컬럼·타입·필수 여부·코드표 목록 |
| 견본 데이터 (100명 가상 코호트) | 양식을 채운 예시. 실제 환자와 무관한 가상데이터입니다 |

처음 준비할 때는 견본 데이터를 한 번 실행해 보면 흐름을 익히기 쉽습니다.

## 견본 데이터로 먼저 시험하기

앱 안의 견본 데이터는 오류가 없는 clean 데이터입니다. 오류가 잡히는 모습까지 보려면 GitHub Release 페이지의 **견본 데이터**(`SampleData-<버전>-all.zip` 또는 코호트별 zip)를 받습니다. 모두 100명 가상 코호트이며 실제 환자와 무관합니다.

| 폴더 | 내용 | 기대 결과 |
|---|---|---|
| `…-<코호트>-clean` | 오류 없는 데이터 | 위반 0건 |
| `…-<코호트>-dirty` | 오류 30여 종을 주입한 데이터 + 정답표 `fault_manifest.csv` | 폴더의 README.txt 에 적힌 위반 건수 |

1. zip 을 풀고 폴더 하나(예: `SampleData-0.1.0-LUNG_CANCER-dirty`)를 **검증 실행** 화면에 끌어다 놓습니다. 폴더 바로 아래의 CSV 가 읽힙니다. 엑셀 입력을 시험하려면 대신 `excel/` 안의 xlsx 파일 하나를 넣습니다. 두 방법의 결과는 같아야 합니다.
2. 폴더의 README.txt 에 적힌 검증 실행일로 **검증 실행일**을 맞춥니다. 미래 날짜 규칙이 이 날짜를 기준으로 판정하기 때문입니다.
3. 실행 결과의 위반 건수가 README 의 참조 결과와 같으면 설치가 정상입니다.
4. dirty 폴더의 `fault_manifest.csv` 를 열면 어떤 행에 어떤 오류를 넣었고 어느 규칙이 잡아야 하는지 볼 수 있습니다. **오류 현황 조회** 화면에서 같은 행을 찾아 대조해 보세요.

## 파일 이름

파일이나 시트 이름이 테이블 이름과 정확히 같지 않아도 됩니다. 프로그램이 이름에 테이블명이 들어 있는지와 헤더가 명세 컬럼과 얼마나 겹치는지(60% 이상)를 보고 자동으로 대응합니다. 자동 대응이 틀렸으면 실행 전 대응표에서 직접 고칠 수 있습니다. 자세한 내용은 [3. 검증 실행](03-run.md)에 있습니다.

## 자주 생기는 준비 오류

- **기본키나 person_id 컬럼이 없음.** 실행이 차단됩니다. 헤더 이름을 명세와 맞춥니다.
- **`antp_therapy_id` 컬럼.** 명세 이름은 `antp_id`입니다. 그대로 넣어도 별칭으로 받아 주지만 주의가 표시됩니다.
- **날짜가 `2026/03/15`나 `20260315` 형식.** 데이터 타입 불일치로 보고됩니다. `YYYY-MM-DD`로 바꿉니다.
- **한글이 깨져 보임.** EUC-KR 파일을 UTF-8로 잘못 저장한 경우입니다. 원본을 다시 내보냅니다.
