# 2. 입력 파일 준비

프로그램은 코호트 데이터를 **파일**로 받습니다. 준비할 것은 두 가지입니다.

| | 무엇 | 누가 | 어떻게 |
|---|---|---|---|
| **EHR 추출본** | 환자·방문·진단·처치·약물·검사·관찰·기록·검체·사망 — OMOP CDM 표 | 병원 정보시스템 | DB 에서 표 단위로 내보냄 |
| **서식** | 병리 보고서·바이오마커·병기·수술·항암·이상사례·가족력과 질환별 검사·평가 — EHR 에 구조화되어 있지 않은 항목 | 코호트 담당자 | 앱이 주는 빈 서식(CSV)을 채움 |

서식은 그대로 검증할 수 없습니다. 앱의 **서식 변환** 화면이 저장 테이블 모양으로 바꿔 주며, 그 결과 폴더를 EHR 추출본 폴더와 **함께** 검증에 넣습니다.

## EHR 추출본: 어떤 표가 필요한가

모든 코호트가 OMOP CDM 5.4 표 14개를 냅니다. 컬럼은 OMOP 표준 그대로이고, `*_concept_id` 에는 K-AI 어휘(값 집합)의 concept_id 를 씁니다.

| 표 | 내용 | 비고 |
|---|---|---|
| PERSON | 환자 | 없으면 실행이 막힙니다 |
| VISIT_OCCURRENCE | 방문 | |
| CONDITION_OCCURRENCE | 진단 | 서식(코호트 인덱스·이상사례)이 행을 보탭니다 |
| PROCEDURE_OCCURRENCE | 처치 | 서식(수술·방사선)이 행을 보탭니다 |
| DRUG_EXPOSURE | 약물 | |
| MEASUREMENT | 검사 | 서식(병기·반응평가·방사선)이 행을 보탭니다 |
| OBSERVATION | 관찰 | 서식(가족력·항암·수술·이상사례)이 행을 보탭니다 |
| NOTE | 기록 | |
| SPECIMEN | 검체 | 병리·바이오마커 서식이 참조합니다 |
| DEATH | 사망 | 사망자가 없어도 헤더만 있는 파일을 넣습니다 |
| OBSERVATION_PERIOD | 관찰기간 | 코호트 인덱스 서식이 만듭니다. EHR 에 있으면 함께 넣어도 됩니다 |
| COHORT | 코호트 소속 | 코호트 인덱스 서식이 만듭니다 |
| EPISODE | 질병·치료 에피소드 | 코호트 인덱스·항암 서식이 만듭니다 |
| EPISODE_EVENT | 에피소드-사건 연결 | 서식이 만듭니다 |

여기에 코호트마다 **K-AI 확장 표** 3~5개가 더 있습니다. 이 표들은 서식에서 만들어지므로 EHR 에서 뽑을 것이 없습니다.

| 코호트 | 확장 표 |
|---|---|
| 폐암 | PATHOLOGY_REPORT, PATHOLOGY_TUMOR, BIOMARKER, LUNG_EXAM |
| 유방암 | PATHOLOGY_REPORT, PATHOLOGY_TUMOR, BIOMARKER, BREAST_BASELINE, BREAST_EXAM |
| 대장암 | PATHOLOGY_REPORT, PATHOLOGY_TUMOR, BIOMARKER, COLORECTAL_EXAM, COLORECTAL_SURGERY_DETAIL |
| 대사이상지방간 | PATHOLOGY_REPORT, MASLD_EXAM, MASLD_ASSESSMENT, MASLD_EVENT |
| 당뇨병 | BIOMARKER, DIABETES_BASELINE, DIABETES_EVENT |
| 림프종 | PATHOLOGY_REPORT, BIOMARKER, LYMPHOMA_ASSESSMENT, LYMPHOMA_EVENT, LYMPHOMA_EXAM |

표가 빠지면 "테이블 없음"으로 보고되고 그 표에 관한 규칙은 건너뜁니다. **해당 사례가 없더라도 헤더만 있는 빈 파일을 넣는** 편이 좋습니다. 그래야 "없어서 못 본 것"과 "있는데 비어 있는 것"이 구분됩니다.

## 서식: 어떤 서식을 채우나

서식은 24종이고 코호트마다 12~14개를 씁니다. 파일 하나가 서식 하나이며 첫 줄이 필드 이름입니다.

| 서식 | 내용 | 코호트 |
|---|---|---|
| COHORT_INDEX | 코호트 인덱스 (등록일, 진단, 관찰기간) | 모두 |
| ADVERSE_EVENT | 이상사례 | 모두 |
| FAMILY_HISTORY | 가족력 | 림프종 제외 |
| PATHOLOGY_REPORT | 병리 보고서 (생검·수술) | 당뇨병 제외 |
| PATHOLOGY_TUMOR | 병리 종양 (보고서의 자식) | 폐암·유방암·대장암 |
| BIOMARKER | 분자·바이오마커 | 대사이상지방간 제외 |
| STAGING | 진단·병기 평가 | 암·림프종 |
| SURGERY | 수술 | 암·대사이상지방간 |
| RADIOTHERAPY | 방사선 코스 | 암·림프종 |
| ANTP_THERAPY | 항암·전신치료 에피소드 | 암·림프종 |
| RESPONSE_ASSESSMENT | 반응·경과 평가 | 암·림프종 |
| LUNG_EXAM | 폐암 검사 | 폐암 |
| BREAST_BASELINE · BREAST_EXAM | 유방암 기저(생식·산과력) · 검사 | 유방암 |
| COLORECTAL_EXAM · COLORECTAL_SURGERY_DETAIL | 대장암 검사 · 수술 세부 | 대장암 |
| MASLD_EXAM · MASLD_ASSESSMENT · MASLD_EVENT | 대사이상지방간 검사 · 평가 · 사건 | 대사이상지방간 |
| DIABETES_BASELINE · DIABETES_EVENT | 당뇨병 기저 · 사건 | 당뇨병 |
| LYMPHOMA_ASSESSMENT · LYMPHOMA_EVENT · LYMPHOMA_EXAM | 림프종 평가 · 사건 · 검사 | 림프종 |

빈 서식은 **검증 실행** 화면의 **입력 양식 내려받기 → 서식 양식**에서 받습니다. 폴더 안의 `README.txt` 에 서식마다 행 단위(환자 1, 검사 1, 보고서 1 …)와, 값을 고르는 필드에 적을 수 있는 **코드 목록**이 있습니다. 코드는 한글 라벨이 아니라 코드를 그대로 적습니다(예: `BIOPSY`, `SURGICAL`, `G2`). `person_id` 는 모든 서식에 있어야 하며 EHR 추출본의 `person_id` 와 같은 값이어야 합니다.

채운 서식 폴더를 **서식 변환** 화면에 넣으면 저장 테이블로 바뀝니다. 자세한 내용은 [3. 검증 실행](03-run.md)의 "서식 변환"에 있습니다.

## 받는 파일 형태

| 형태 | 설명 |
|---|---|
| CSV 여러 개 | 파일 하나가 표 하나. UTF-8 또는 EUC-KR(자동 변환). 탭·세미콜론 구분도 알아서 읽습니다 |
| 엑셀 한 파일 | 시트 하나가 표 하나. 날짜 셀은 자동으로 YYYY-MM-DD로 바뀝니다 |
| 폴더 | 위 파일들이 든 폴더. **여러 개 넣어도 됩니다** — EHR 추출본 폴더와 서식 변환 결과 폴더가 따로여도 그대로 넣으세요. 두 폴더를 담은 상위 폴더 하나를 넣어도 됩니다 |

같은 이름의 표가 두 폴더에서 오면 **합쳐 읽습니다**. EHR 추출본의 MEASUREMENT(검사 결과)와 서식 변환 결과의 MEASUREMENT(병기 평가)가 한 표를 나눠 갖기 때문입니다. 사전 점검이 "2개 파일을 합쳐 읽습니다"로 알려 줍니다.

## 값의 형식

| 항목 | 형식 |
|---|---|
| 문자 인코딩 | UTF-8 권장. EUC-KR(CP949)도 자동 인식해 변환합니다 |
| 헤더 | 첫 줄에 컬럼 이름. 명세의 컬럼 이름과 같아야 합니다. 대문자로 나와도(`PERSON_ID`) 알아서 맞춥니다 |
| 빈 값(NULL) | 빈 문자열. `NULL`, `NA`, `N/A` 같은 글자가 들어 있으면 빈 값으로 읽고 몇 개였는지 보고서에 적습니다 |
| 날짜 | `YYYY-MM-DD` (예: 2026-03-15). `2026-03-15 00:00:00` 처럼 시각이 붙어 나오면 날짜만 읽습니다 |
| 타임스탬프 | `YYYY-MM-DD HH:MM:SS` |
| 정수 | 숫자만. `100001.0` 처럼 `.0` 이 붙어 나오면 정수로 읽습니다 |
| 숫자 | 숫자만. 단위나 천 단위 쉼표(`1,234`)를 넣지 않습니다 — 이것은 고쳐 주지 않고 위반으로 보고합니다 |

위 표의 "알아서 읽는" 것들은 내보내기 도구가 남긴 흔적이라 검증 전에 걷어 내고, 무엇을 얼마나 걷어 냈는지 `report.md` 의 **입력 정규화** 절에 적습니다. 뜻이 하나로 정해지는 경우만 손대며, `2026/03/15` 같은 다른 날짜 형식이나 엑셀 일련번호(`45000`)는 손대지 않고 위반으로 보고합니다.

## 입력 양식 내려받기

**검증 실행** 화면의 **입력 양식 내려받기**에서 다섯 가지를 받을 수 있습니다.

| 양식 | 용도 |
|---|---|
| 엑셀 양식 (시트당 테이블, 명세 포함) | 표마다 헤더가 채워진 빈 양식. 명세 시트가 함께 들어 있습니다 (EHR 추출본용) |
| CSV 양식 묶음 (헤더만) | 표별 CSV 헤더 파일 (EHR 추출본용) |
| 컬럼 명세서 (xlsx) | 표·컬럼·한글 이름·타입·필수 여부·값 집합 목록 |
| 견본 데이터 (100명 가상 코호트) | 양식을 채운 예시. 실제 환자와 무관한 가상데이터입니다 |
| 서식 양식 (병원이 채울 빈 서식 · CSV) | 코호트의 서식 12~14개와 코드 목록 README |

## 견본 데이터로 먼저 시험하기

앱 안의 견본 데이터는 오류가 없는 clean 데이터입니다. 오류가 잡히는 모습까지 보려면 GitHub Release 페이지의 **견본 데이터**(`SampleData-<버전>-all.zip` 또는 코호트별 zip)를 받습니다. 모두 100명 가상 코호트이며 실제 환자와 무관합니다.

| 폴더 | 내용 | 기대 결과 |
|---|---|---|
| `…-<코호트>-clean` | 오류 없는 데이터 | 위반 0건 |
| `…-<코호트>-dirty` | 오류 80~120건을 주입한 데이터 + 정답표 `fault_manifest.csv` | 폴더의 README.txt 에 적힌 위반 건수 |

1. zip 을 풀고 폴더 하나(예: `SampleData-0.2.0-LUNG_CANCER-dirty`)를 **검증 실행** 화면에 끌어다 놓습니다. 엑셀 입력을 시험하려면 대신 `excel/` 안의 xlsx 파일 하나를 넣습니다. 두 방법의 결과는 같아야 합니다.
2. 폴더의 README.txt 에 적힌 검증 실행일로 **검증 실행일**을 맞춥니다. 미래 날짜 규칙이 이 날짜를 기준으로 판정하기 때문입니다.
3. 실행 결과의 위반 건수가 README 의 참조 결과와 같으면 설치가 정상입니다.
4. dirty 폴더의 `fault_manifest.csv` 를 열면 어떤 행에 어떤 오류를 넣었고 어느 규칙이 잡아야 하는지 볼 수 있습니다. **오류 현황 조회** 화면에서 같은 행을 찾아 대조해 보세요.

## 파일 이름

파일이나 시트 이름이 표 이름과 정확히 같지 않아도 됩니다(`person_20260901.csv` 도 됩니다). 프로그램이 이름에 표 이름이 들어 있는지와 헤더가 명세 컬럼과 얼마나 겹치는지(60% 이상)를 보고 자동으로 대응합니다. 자동 대응이 틀렸으면 실행 전 대응표에서 직접 고칠 수 있습니다.

## 자주 생기는 준비 오류

- **PERSON 이 없음.** 실행이 차단됩니다. 모든 표가 환자에 매달리기 때문입니다.
- **기본키나 person_id 컬럼이 없음.** 실행이 차단됩니다. 헤더 이름을 명세와 맞춥니다.
- **서식의 코드가 목록에 없음.** 서식 변환의 '확인할 점'에 나옵니다. 서식 양식의 README.txt 에 있는 코드를 씁니다.
- **서식 변환 결과만 넣고 EHR 추출본을 빼먹음.** PERSON 이 없어 실행이 막히거나, 환자·방문·약물 표가 '테이블 없음'으로 나옵니다. 두 폴더를 함께 넣습니다.
- **날짜가 `2026/03/15`나 `20260315` 형식.** 데이터 타입 불일치로 보고됩니다. `YYYY-MM-DD`로 바꿉니다.
- **한글이 깨져 보임.** EUC-KR 파일을 UTF-8로 잘못 저장한 경우입니다. 원본을 다시 내보냅니다.
