# 5. 자주 묻는 질문

## 설치와 실행

**설치 파일을 실행하면 보안 경고가 뜹니다.**
설치 파일은 코드 서명과 공증이 되어 있어 정상 파일이면 경고가 뜨지 않습니다. 경고가 뜨면 내려받기 중 손상되었거나 Release 페이지가 아닌 곳에서 받은 파일입니다. Release 페이지에서 다시 받고, 필요하면 `SHA256SUMS.txt` 와 대조합니다.

**인터넷이 안 되는 PC에서도 되나요?**
됩니다. 프로그램은 네트워크 통신을 하지 않으며 명세와 규칙이 안에 들어 있습니다.

**실행 이력은 어디에 저장되나요?**
사용자 컴퓨터의 앱 데이터 폴더에 DuckDB 파일 하나로 저장됩니다. 위치는 **설정** 화면에서 볼 수 있습니다. 다른 곳으로 전송되지 않습니다.

## 입력 파일

**파일을 넣었는데 테이블이 대응되지 않습니다.**
파일 이름에 테이블명이 없고 헤더도 명세 컬럼과 60% 미만으로 겹치면 자동 대응이 되지 않습니다. 대응표의 드롭다운에서 직접 고르거나, 파일 이름을 테이블명(예: `PERSON.csv`)으로 바꿉니다.

**엑셀 파일의 시트가 일부만 인식됩니다.**
시트 하나가 테이블 하나여야 합니다. 시트 이름에 테이블명을 넣으면 확실합니다. 첫 줄이 헤더가 아니거나 제목 행이 있으면 지웁니다.

**한글이 깨져 보입니다.**
파일이 EUC-KR인데 다른 인코딩으로 잘못 저장된 경우입니다. 병원 시스템에서 다시 내보내거나, 엑셀에서 열어 UTF-8 CSV로 저장합니다. 정상 EUC-KR 파일은 프로그램이 알아서 변환합니다.

**"기본키 또는 person_id 누락" 오류로 실행이 막힙니다.**
헤더에 그 테이블의 기본키(예: `visit_occurrence_id`)와 `person_id` 컬럼이 있어야 합니다. 컬럼 이름의 대소문자와 철자를 명세와 맞춥니다. 컬럼 명세서는 **입력 양식 내려받기**에서 받을 수 있습니다.

**`antp_therapy_id` 컬럼을 그대로 써도 되나요?**
됩니다. `antp_id`의 별칭으로 인식하고 주의만 표시합니다. 가능하면 `antp_id`로 바꿔 제출합니다.

**날짜가 `2026/03/15`처럼 되어 있습니다.**
`YYYY-MM-DD`로 바꿔야 합니다. 엑셀에서는 셀을 날짜 형식으로 두면 프로그램이 변환합니다. CSV에서는 내보낼 때 형식을 지정합니다.

## 결과

**위반이 너무 많이 나옵니다. 어디부터 봐야 하나요?**
**결과 보고서**의 실패 규칙 목록을 위반 수 순으로 봅니다. 컬럼 구성 불일치나 데이터 타입 불일치처럼 형식 문제 하나가 수천 건을 만드는 경우가 많으니 형식 문제를 먼저 고치고 다시 실행합니다.

**코드 유효성 경고가 OMOP concept에서 나옵니다.**
프로그램은 OMOP 표준 concept의 최소 허용집합만 검사하므로 병원이 쓰는 다른 표준 concept이 경고로 나올 수 있습니다. 이 규칙은 경고(Medium)이며 제출을 막지 않습니다. 전체 OMOP 어휘 검증은 병원 DB에서 OHDSI DataQualityDashboard로 합니다.

**미래 날짜 오류가 나오는데 실제로는 맞는 날짜입니다.**
검증 실행일 기준으로 판정합니다. **설정** 또는 실행 화면의 **검증 실행일**을 데이터 추출일로 맞추고 다시 실행합니다.

**어떤 파일을 중앙에 보내나요?**
`submission.json` 하나입니다. `findings.csv`와 오류 현황에서 내보낸 CSV는 환자 단위 정보이므로 보내지 않습니다.

**규칙 내용을 미리 볼 수 있나요?**
**검증 규칙 관리** 화면에서 규칙 1,196개를 검색해 설명, 검사 대상, 교차 규칙의 SQL, 조치 안내를 볼 수 있습니다.
