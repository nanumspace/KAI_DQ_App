# Quality Validator 사용자 설명서

병원 담당자가 코호트 데이터를 제출하기 전에 스스로 품질을 점검하는 프로그램입니다. EHR 에서 뽑은 표와 담당자가 채운 서식을 넣고 실행하면 검증 규칙 1,078개(코호트마다 341~531개가 적용)를 검사해 보고서를 만듭니다.

- 병원 데이터베이스에 접속하지 않습니다. 내보낸 파일만 읽습니다.
- 네트워크 통신을 하지 않습니다. 결과는 사용자 컴퓨터에만 저장됩니다.
- 환자 단위 정보는 프로그램 밖으로 나가지 않습니다. 중앙에 보내는 파일은 집계만 담은 `submission.json` 하나입니다.

## 데이터가 오가는 길

```
EHR 추출본 (환자·방문·약물·검사 … OMOP 표)  ─┐
                                              ├─→  검증 실행  →  보고서 · submission.json
서식 (병리·바이오마커·병기·수술 … 담당자가 채움) ─→ 서식 변환 ─┘
```

병원이 준비하는 것은 두 가지입니다. **EHR 추출본**은 병원 정보시스템에서 그대로 뽑는 표이고, **서식**은 EHR 에 구조화되어 있지 않아 담당자가 채우는 항목입니다. 서식은 앱의 **서식 변환** 화면이 저장 테이블 모양으로 바꿔 주며, 그 결과를 EHR 추출본과 함께 **검증 실행** 화면에 넣습니다.

## 화면 구성

왼쪽 메뉴에 8개 화면이 있습니다. 처음 열면 **검증 실행** 화면이 나옵니다.

| 메뉴 | 용도 |
|---|---|
| 검증 실행 | 코호트와 파일을 넣고 검증을 실행합니다. 결과 파일을 내보냅니다 |
| 서식 변환 | 담당자가 채운 서식 폴더를 저장 테이블로 바꿉니다 |
| 결과 보고서 | 실행 요약, 실패 규칙, 분류별 집계, 보고서 원문 |
| 오류 현황 조회 | 위반 행을 규칙·테이블·심각도로 걸러 보고 CSV로 내보냅니다 |
| 대시보드 | 오류 유형별 통계, 질환별 최신 결과, 적용 규칙, 후속 조치 가이드, 실행 추이 |
| 통계 모니터링 | 실행 이력 목록과 위반 건수·오류율 추이, 실행 기록 삭제 |
| 검증 규칙 관리 | 규칙 조회·검색, 규칙 설명과 조치 안내 |
| 설정 | 명세 판, 명세·규칙 위치, 검증 실행일 기본값, 데이터 저장 위치 |

## 명세 판

이 설명서는 **v2** 명세(OMOP CDM 5.4 + K-AI 확장) 기준입니다. 이전에 v1 명세(질환별 단일 표)로 낸 제출본을 다시 열어 볼 일이 있으면 **설정 → 명세 판**에서 v1 을 고를 수 있습니다. 판을 바꾸면 코호트·규칙·양식·견본 데이터가 함께 바뀝니다.
