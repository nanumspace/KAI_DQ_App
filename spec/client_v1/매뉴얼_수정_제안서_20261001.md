## 1. 의뢰사 확인 질문

### Q01. concept ID를 어느 Athena 어휘 판본 기준으로 정할까요?

같은 숫자 ID라도 판본에 따라 표준 여부·domain이 바뀔 수 있습니다. 판본이 정해져야 concept ID의 존재·표준성 DQ를 재현할 수 있습니다.

- 의뢰사가 판본(다운로드 일자)을 지정 → 지정 판본으로 매핑하고 검증합니다.
- 개발 측이 현재 판본을 고정해 공유 → 고정한 판본 정보를 매뉴얼 부록에 기록합니다.

상태: 답변: **개발 측이 현재 판본을 고정해 공유**

### Q02. 범주형 결과값(예/아니오, 폐경 상태 등)도 concept ID로 저장할까요?

현재 OBSERVATION에는 결과용 concept 열이 없어 결과는 숫자 코드나 문자열로만 남습니다. concept ID로 저장해야 '임신 여부=예'처럼 기관 간 같은 의미로 비교·검증할 수 있습니다.

- 예, 결과도 concept ID로 저장 → OBSERVATION에 value_as_concept_id 열을 추가합니다(제안 C08).
- 아니오, 항목만 concept ID로 저장 → 결과는 문자열로만 보존하며 결과 의미의 DQ는 하지 않습니다.

상태: 답변: **예, 결과도 concept ID로 저장**

### Q03. diag_rgst_ymd(진단정보 등록일)는 실제 진단일과 같은가요?

폐암·유방암·대장암 표에는 '등록일'만 있습니다. 등록이 진단보다 늦으면 '진단 전 치료' 같은 시간 순서 오류를 잘못 판정합니다.

- 같다 (등록일 = 진단일) → 현재 열을 진단일로 사용합니다. 설명 문구만 정정합니다.
- 다르며, 실제 진단일 데이터가 있다 → 진단일 열을 추가합니다(제안 C07).
- 다르지만 실제 진단일 데이터는 없다 → 등록일을 근사값으로만 쓰고 날짜 순서 DQ는 경고 수준으로 낮춥니다.

상태: 답변: **같다 (등록일 = 진단일)**

### Q04. 폐암 clinical_stage의 AJCC 판수를 알 수 있나요?

OMOP 병기 개념은 판수(6·7·8판)별로 다릅니다. 판수가 없으면 'IIA'를 표준 병기 개념에 대응시킬 수 없습니다.

- 환자마다 판수가 원천에 기록되어 있다 → 판수 열을 추가합니다(제안 C04).
- 모두 같은 판수(예: 8판)로 기록한다 → 설명에 판수를 명시합니다(제안 C05).
- 알 수 없다 → 병기는 원천 문자열로만 보존하고 표준 병기 매핑·DQ를 하지 않습니다.

상태: 답변: **환자마다 판수가 원천에 기록되어 있다**

### Q05. 폐암 조직형의 ICD-O-3 형태 코드(예: 8140/3)와 원발 부위 코드(예: C34.1)가 원천에 있나요?

OMOP 종양 관례는 암 진단을 ICD-O-3 조직형+부위 개념으로 CONDITION에 기록합니다. 현재 1~7 범주(예: '기타', 'Carcinoma tumor 계열')로는 표준 개념에 1:1로 대응시킬 수 없습니다.

- 있다 → ICD-O-3 코드 열을 추가합니다(제안 C06).
- 없다, 1~7 범주만 있다 → 범주별로 가장 가까운 표준 진단 개념에 매핑하고 '기타'는 일반 폐암 개념으로 둡니다.

상태: 답변: **있다**

### Q06. 비항암 약물(예: 가임력 보존용 GnRHa)도 DRUG_EXPOSURE에 넣나요?

현재 sact_id와 note_id가 모두 필수(Y)라서 항암요법·노트가 없는 약물은 저장할 수 없습니다.

- 넣는다 → sact_id·note_id를 조건부 필수로 바꿉니다(제안 C02·C03).
- 넣지 않는다 (항암 약물만) → 현재 필수 조건을 유지합니다. 비항암 약물은 수집 범위에서 빠집니다.

상태: 답변: **넣는다**

### Q07. 항암요법(SACT) 정보를 어떤 구조로 둘까요?

OMOP CDM 5.4는 레지멘·치료 line을 EPISODE/EPISODE_EVENT 표준 테이블로 표현합니다. 전환하면 DRUG_EXPOSURE.sact_id 같은 비표준 연결이 필요 없고 표준 도구와 호환됩니다.

- 현재 SACT 특화 테이블 유지 → DRUG_EXPOSURE.sact_id 연결을 유지합니다.
- EPISODE/EPISODE_EVENT로 전환 → SACT 시트를 EPISODE 매핑으로 바꿉니다(제안 C12).

상태: 답변: **현재 SACT 특화 테이블 유지**

### Q08. 검사·관찰 값이 '어느 수술/진단'에 속하는지까지 검증해야 하나요?

같은 방문에 수술이 두 번 있으면 지금 구조로는 TME 완전도가 어느 수술의 평가인지 알 수 없습니다. CDM 5.4는 이를 위한 표준 연결 열을 제공합니다.

- 예, 사건 단위로 검증 → 표준 사건 연결 열을 추가합니다(제안 C11).
- 아니오, 환자·방문 단위로 충분 → 연결 열 없이 진행합니다. 사건 간 값 뒤바뀜은 검출하지 못합니다.

상태: 답변: **아니오, 환자·방문 단위로 충분**

### Q09. 병원 고유(로컬) 코드의 concept ID도 보존해야 하나요?

표준 개념이 없거나 나중에 매핑이 바뀌어도 원래 병원 항목으로 되돌아가려면 로컬 concept ID를 별도 열에 둬야 합니다.

- 예 → *_source_concept_id 열을 추가합니다(제안 C10).
- 아니오, 원천 코드 문자열로 충분 → 제안 C09의 원천 코드 문자열만 보존합니다.

상태: 답변: **아니오, 원천 코드 문자열로 충분**

### Q10. 질환별 특화 테이블(DIABETES 등)을 계속 제출하나요?

특화 테이블을 없애고 공통 테이블만 쓰려면, 그 테이블에만 있는 정보(예: 당뇨 진단 종료일)를 담을 열이 공통 테이블에 있어야 합니다.

- 계속 제출 → 공통 테이블 열 추가가 필요 없습니다.
- 없애고 공통 테이블로 이전 → CONDITION_OCCURRENCE 종료일 등 열을 추가합니다(제안 C13).

상태: 답변: **계속 제출**

### Q11. 약물의 SMILES 구조식은 투약 기록마다 필요한가요?

구조식은 환자 투약이 아니라 약물 자체의 속성입니다. 투약마다 NOTE를 연결하면 같은 구조식이 수천 번 중복되고 note_id 필수 오류가 생깁니다.

- 성분별 참조표 한 번이면 된다 → 성분별 참조표를 두고 DRUG_EXPOSURE.note_id를 없앱니다(제안 C14).
- 투약 기록마다 연결해야 한다 → 현재 note_id 구조를 유지합니다.

상태: 답변: **성분별 참조표 한 번이면 된다**

### Q12. 소세포폐암 병기를 어떤 체계로 기록하나요?

소세포폐암(조직형 4)은 AJCC 대신 제한기/확장기(VALSG)로 기록하는 경우가 많습니다. AJCC 칸에 제한기/확장기가 들어오면 표준 매핑과 DQ가 모두 실패합니다.

- AJCC 병기로만 기록 → 현재 규칙(판수별 AJCC 병기)을 그대로 적용합니다.
- 제한기/확장기로만 기록 → 소세포폐암에 LD/ED 값을 허용합니다(제안 C21).
- 병원·환자에 따라 둘 다 있음 → AJCC와 LD/ED를 모두 허용하고 판수 유무로 구분합니다(제안 C21).

상태: 답변: **병원·환자에 따라 둘 다 있음**

## 2. 매뉴얼 수정 제안

### C01. LYMPHOMA.cell_of_origin 필수 Y → N (DLBCL일 때만 입력) (필수)

- 적용 조건: 항상 권장 (질문 답과 무관) → **항상 권장**
- 검토 결정: 채택

현재:
```
림프종(LYMPHOMA) 7행 cell_of_origin | varchar | 필수 Y | DLBCL 세포기원 분류이다. 예: GCB, ABC/non-GCB, unclassifiable.
```
제안:
```
필수: N
설명: DLBCL 세포기원 분류이다. DLBCL 환자인 경우에만 입력한다. 예: GCB, ABC/non-GCB, unclassifiable.
```
이유: 세포기원은 DLBCL에만 존재하는 분류입니다. Y로 두면 다른 림프종 환자 전원이 결측 오류로 판정됩니다.

예시: 호지킨 림프종 환자의 cell_of_origin이 비어 있음 → 현재: 필수 결측 오류 / 수정 후: 정상. DLBCL 환자인데 비어 있으면 DQ 규칙이 별도로 경고합니다.

### C02. DRUG_EXPOSURE.sact_id 필수 Y → N (항암제 투여일 때만 필수) (필수)

- 적용 조건: Q06 = 넣는다 그리고 Q07 = 현재 SACT 특화 테이블 유지 → **필요 (질문 답 기준)**
- 검토 결정: 채택

현재:
```
약물 노출(DRUG_EXPOSURE) 6행 sact_id | integer | 필수 Y | SACT 테이블과 연결되는 외래키 식별자이다.
```
제안:
```
필수: N (조건부)
설명: SACT 테이블과 연결되는 외래키이다. 항종양제(ATC L01)는 항암요법으로 투여되므로 필수이다. 내분비 치료제(ATC L02, 예: GnRHa·타목시펜)는 항암요법으로 투여한 경우에만 입력한다. 그 외 약물은 비워 둔다.
```
이유: 비항암 약물에는 연결할 항암요법이 없습니다. 또한 '항암요법일 때만 필수'를 DQ로 검사하려면 무엇이 항암제인지 판정 기준이 있어야 합니다. ATC L01은 항상 항암 목적이라 필수로 검사할 수 있고, L02는 가임력 보존처럼 비항암 목적에도 쓰여 강제할 수 없으므로 구분합니다.

예시: 옥살리플라틴(L01) 투여, sact_id 비어 있음 → 필수 결측 오류. GnRHa(L02, 가임력 보존) 투여, sact_id 비어 있음 → 정상(DQ는 '목적 확인' 안내만). 메트포르민(A10), sact_id 비어 있음 → 정상.

### C03. DRUG_EXPOSURE.note_id 필수 Y → N (필수)

- 적용 조건: Q06 = 넣는다 그리고 Q11 = 투약 기록마다 연결해야 한다 → **불필요 (질문 답 기준)**
- 검토 결정: 채택 안 함

현재:
```
약물 노출(DRUG_EXPOSURE) 7행 note_id | integer | 필수 Y | 노트에 대한 고유 식별자이다. AI 학습용 의약품의 화학 구조식 (Smiles code)은 Note 레코드로 매핑한다.
```
제안:
```
필수: N
설명: 해당 투약과 연결되는 노트가 있는 경우에만 입력한다.
```
이유: SMILES 노트가 없는 약물(비항암제 등)은 저장할 수 없게 됩니다.

예시: 구조식 노트가 없는 GnRHa 투여 기록: note_id = 비움(정상).

### C04. LUNG_CANCER에 clinical_stage_ajcc_edition 열 추가, 병기 값은 판수별로 (필수)

- 적용 조건: Q04 = 환자마다 판수가 원천에 기록되어 있다 → **필요 (질문 답 기준)**
- 검토 결정: 채택

현재:
```
폐암(LUNG_CANCER) 9행 clinical_stage | varchar | 필수 Y | 초진 시 AJCC 임상 병기를 나타내는 값이다. IA, IB, IIA, IIB, IIIA, IIIB, IV 등으로 기입한다.
```
제안:
```
신규 열 (clinical_stage 다음)
필드명: clinical_stage_ajcc_edition | integer | 필수 Y
설명: clinical_stage 판정에 사용한 AJCC 판수이다. 6, 7, 8 중 하나로 기입한다.

clinical_stage 설명 변경: 초진 시 AJCC 임상 병기이다. clinical_stage_ajcc_edition 판수의 병기군으로 기입한다. 8판: 0, IA1, IA2, IA3, IB, IIA, IIB, IIIA, IIIB, IIIC, IVA, IVB / 7판: 0, IA, IB, IIA, IIB, IIIA, IIIB, IV
```
이유: OMOP 표준 병기 개념(Cancer Modifier)은 판수별로 다른 개념입니다(예: c-8th_AJCC/UICC-Stage-2A). 판수 없이는 표준 매핑이 불가능합니다. 기존 설명의 예시(IA, IB … IV)는 7판 값이라 8판 환자에게 맞지 않으므로 판수별 허용 값을 함께 고칩니다.

예시: clinical_stage = IA2, 판수 8 → 정상. clinical_stage = IA2, 판수 7 → 7판에 없는 값이므로 DQ 오류. clinical_stage = IIA, 판수 8 → '임상 AJCC 8판 IIA' 개념으로 매핑.

### C05. LUNG_CANCER.clinical_stage 설명에 AJCC 판수 명시 (필수)

- 적용 조건: Q04 = 모두 같은 판수(예: 8판)로 기록한다 → **불필요 (질문 답 기준)**
- 검토 결정: 채택 안 함

현재:
```
폐암(LUNG_CANCER) 9행 clinical_stage | varchar | 필수 Y | 초진 시 AJCC 임상 병기를 나타내는 값이다. IA, IB, IIA, IIB, IIIA, IIIB, IV 등으로 기입한다.
```
제안:
```
설명: 초진 시 AJCC 8판 기준 임상 병기를 나타내는 값이다. IA1, IA2, IA3, IB, IIA, IIB, IIIA, IIIB, IIIC, IVA, IVB 등으로 기입한다.
```
이유: 판수가 하나로 고정되면 열 추가 없이 설명만으로 표준 매핑이 가능합니다. 8판을 쓰면 IA1~IA3, IIIC, IVA/IVB 같은 세분 값도 허용해야 합니다.

예시: clinical_stage = IA2 → 8판 IA2 개념. 8판에 없는 값(예: 단독 'IA')은 DQ에서 판수 불일치로 경고합니다.

### C06. LUNG_CANCER에 ICD-O-3 조직형·부위 코드 열 추가 (필수) (필수)

- 적용 조건: Q05 = 있다 → **필요 (질문 답 기준)**
- 검토 결정: 채택

현재:
```
폐암(LUNG_CANCER) 7행 histologic_diagnosis | integer | 필수 Y | 원발 진단(조직형) 원천 코드이다.
1=Adenocarcinoma, 2=Squamous cell carcinoma, 3=Large cell carcinoma, 4=Small cell carcinoma, 5=Carcinoma tumor 계열, 6=NSCLC NOS, 7=기타
```
제안:
```
신규 열 2개 (histologic_diagnosis 다음)
histology_icdo3_code | varchar | 필수 Y | ICD-O-3 형태 코드 (예: 8140/3)
primary_site_icdo3_code | varchar | 필수 Y | ICD-O-3 부위 코드 (예: C34.1)
```
이유: OHDSI 종양 관례는 암 진단을 ICD-O-3 '조직형-부위' 개념으로 CONDITION_OCCURRENCE에 기록합니다. 1~7 범주는 표준 개념과 1:1로 대응하지 않습니다(특히 5 'Carcinoma tumor 계열', 7 '기타'). 원천에 코드가 있으므로(Q05) 필수로 두어 누락을 잡고, 1~7 범주와 코드의 일치 여부도 검사합니다.

제안:
```
예) 외래 = 9202 (Outpatient Visit), 입원 = 9201 (Inpatient Visit), 응급 = 9203 (Emergency Room Visit)
※ Q01 판본에서 최종 확인 후 기재
```
이유: '00000000'은 자리표시자라 병원이 실제 값을 알 수 없습니다. 방문 유형은 OMOP 표준 Visit 개념이 널리 고정되어 있습니다.

예시: 외래 방문 행: visit_concept_id = 9202.

시트 제목: 5.1 이상사례(ADVERSE_EVENT) — SACT 시트와 번호 중복

### C19. LYMPHOMA에 ICD-O-3 조직형 코드 열 추가 (아형 판별) (필수)

- 적용 조건: 항상 권장 (질문 답과 무관) → **항상 권장**
- 검토 결정: 채택

현재:
```
림프종(LYMPHOMA) 6행 diagnosis_date | date | 필수 Y | 림프종을 최초로 확진한 날짜이다.
림프종(LYMPHOMA) 7행 cell_of_origin | varchar | 필수 Y | DLBCL 세포기원 분류이다. 예: GCB, ABC/non-GCB, unclassifiable.
```
제안:
```
신규 열 (diagnosis_date 다음)
histology_icdo3_code | varchar | 필수 Y | 림프종 ICD-O-3 형태 코드 (예: DLBCL 9680/3, 외투세포 9673/3, 고전적 호지킨 9650/3, 말초 T세포 NOS 9702/3)
```
이유: 현재 LYMPHOMA 표에는 아형 정보가 없어 cell_of_origin(DLBCL), mipi_score(외투세포), hodgkin_ips_score(호지킨), pit_score(T세포)가 누구에게 해당하는지 DQ가 알 수 없습니다. C01(cell_of_origin Y→N)의 'DLBCL이면 입력' 규칙도 이 열이 있어야 검사할 수 있습니다. 진단 CONDITION 매핑(ICD-O-3 관례)에도 필요합니다.

예시: histology_icdo3_code = 9680/3(DLBCL), cell_of_origin 비어 있음 → 조건부 필수 결측 경고. 9650/3(호지킨), cell_of_origin 비어 있음 → 정상. 9673/3(외투세포), mipi_score 비어 있음 → 권장 항목 결측 안내.

### C20. diag_rgst_ymd 설명을 '진단일'로 정정 (폐암·유방암·대장암) (필수)

- 적용 조건: Q03 = 같다 (등록일 = 진단일) → **필요 (질문 답 기준)**
- 검토 결정: 채택

현재:
```
폐암(LUNG_CANCER) 6행 diag_rgst_ymd | date | 필수 Y | 진단정보 등록 연월일이다.
유방암(BREAST_CANCER) 6행 diag_rgst_ymd | date | 필수 Y | 진단정보 등록 연월일이다.
대장암(COLORECTAL_CANCER) 6행 diag_rgst_ymd | date | 필수 Y | 진단정보 등록 연월일이다.
```
제안:
```
설명: 해당 암을 최초로 진단(조직학적 확진)한 날짜이다. 진단정보 등록일과 동일하다.
```
이유: 현재 설명 '진단정보 등록 연월일'만 보면 병원마다 실제 등록 작업일을 넣을 수 있습니다. 진단일과 같다고 확인했으므로(Q03) 의미를 문구로 고정해야 날짜 순서 DQ가 맞습니다.

예시: 병원 A는 진단일, 병원 B는 전산 등록일을 입력 → 같은 열의 의미가 달라 '진단 전 수술' 판정이 병원마다 틀어짐. 문구 정정 후에는 진단일로 통일.

### C21. 소세포폐암의 제한기/확장기 병기 허용 (필수)

- 적용 조건: Q12 = 제한기/확장기로만 기록 또는 병원·환자에 따라 둘 다 있음 → **필요 (질문 답 기준)**
- 검토 결정: 채택

현재:
```
폐암(LUNG_CANCER) 9행 clinical_stage | varchar | 필수 Y | 초진 시 AJCC 임상 병기를 나타내는 값이다. IA, IB, IIA, IIB, IIIA, IIIB, IV 등으로 기입한다.
```
제안:
```
clinical_stage 설명에 추가: 소세포폐암(histologic_diagnosis = 4)에서 AJCC 병기 대신 VALSG 병기를 쓰는 경우 LD(제한기) 또는 ED(확장기)로 기입하고, clinical_stage_ajcc_edition은 비워 둔다.
```
이유: 소세포폐암은 제한기/확장기로 병기를 기록하는 경우가 많습니다. 이를 AJCC 칸에 억지로 넣거나 결측으로 처리하면 DQ 오류가 납니다. 값과 판수 규칙을 명시해 두 체계를 구분합니다.

예시: histologic_diagnosis = 4, clinical_stage = ED, 판수 비어 있음 → 정상. histologic_diagnosis = 1(선암), clinical_stage = ED → 오류.
